# Security Policy

## Supported Versions

Currently maintained versions receiving security updates:

| Version | Support status |
| --- | --- |
| X.Y | Active maintenance |
| X.Y | Critical fixes only |
| < X.Y | Unsupported |

## Reporting Vulnerabilities

**Please report security issues responsibly** through our secure channel:

| Method | Details |
| --- | --- |
| **Preferred method** | Create a private vulnerability report through GitHub Security Advisories. |
| **Alternative** | Email the security team at `epilif3sotnas@yandex.com`. Include the project name in the subject. |
| **Response time** | Initial acknowledgment within 48 hours. |

**Do not** report security vulnerabilities through public issues, discussions, pull requests, or merge requests.

## Disclosure Policy

1. **Verification:** The security team confirms the vulnerability.
2. **Patch development:** The team creates fixes for supported versions.
3. **Coordinated disclosure:**
   - A security advisory is published.
   - A CVE is assigned, if applicable.
   - Patch releases are issued simultaneously.

## Security Updates

Regular security improvements are implemented through:

- **Dependency scanning** for known vulnerabilities.
- **Automated security testing** in CI/CD pipelines.
- **Third-party audits** for critical components.
